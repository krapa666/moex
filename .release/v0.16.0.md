# MOEX Fair Price v0.16.0

Minor release adding robustness diagnostics for the no-lookahead net-profit consensus backtest introduced in v0.15.0.

## Added

- Added public robustness API:
  - `GET /api/analytics/consensus-backtest/robustness`
- Added weighted-vs-median breakdowns by:
  - fiscal year;
  - ticker.
- Added evaluation leave-one-out diagnostics:
  - exclude one ticker at a time;
  - exclude one fiscal year at a time;
  - recalculate weighted improvement on the remaining evaluation set.
- Added a fixed 27-case parameter sensitivity grid:
  - `shrinkage_samples = 2, 5, 10`;
  - `error_floor_percent = 2.5, 5, 10`;
  - `relative_score_cap = 1.5, 2, 3`.
- Added summary coverage counters and min/max weighted median-sMAPE delta across the parameter grid.
- Added Analytics UI for robustness diagnostics using the same `pre_year` / `mid_year` / `year_end` selector as source accuracy and the main consensus backtest.
- Added backend tests for slice concentration, leave-one-out behavior, the 27-case grid and empty datasets.
- Added Playwright coverage for public robustness rendering and snapshot switching.

## Methodology

The robustness layer does not define a hidden binary `robust=true` threshold. It exposes the evidence needed to judge stability:

- number of ticker slices where weighted median sMAPE beats the median baseline;
- number of year slices where it beats the baseline;
- number of leave-one-ticker-out and leave-one-year-out cases where improvement remains positive;
- number of parameter combinations where improvement remains positive;
- worst and best median-sMAPE delta across the parameter grid.

Leave-one-out is an **evaluation jackknife**: the excluded ticker/year is removed from the scored observation set, while already-valid historical training information for the remaining observations is preserved. This tests whether the aggregate result is dominated by one evaluation segment without changing the weighting algorithm itself.

The parameter grid preserves the v0.15.0 no-lookahead rules. Historical samples may train a source weight only when their fiscal year is older than the target year and the canonical actual has a known `reported_at` strictly before the target cutoff.

## Privacy

The robustness response contains only aggregate metrics, fiscal years and public MOEX tickers. It does not expose analyst names, source-level forecasts or source weights and is safe for internet/read-only Analytics.

Detailed source-level observations remain available only through the existing local-only endpoint:

```http
GET /api/analytics/consensus-backtest/observations
```

## Production consensus

**v0.16.0 still does not enable accuracy-weighted production consensus.**

Fair-value formulas, current target-price consensus, Watchlist ranking, expected-return calculations and volume-monitor logic remain unchanged. Robustness diagnostics are the next evidence gate before any production weighting decision.

## Database and configuration
