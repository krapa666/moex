# MOEX Fair Price v0.26.0

Minor release adding Actual Results Coverage diagnostics for the historical forecast evidence layer.

## Added

- Added read-only coverage endpoint:
  - `GET /api/analytics/actual-net-profits/coverage`
- Added no-hindsight coverage calculation over existing `forecast_revisions` and `actual_net_profits`.
- Added aggregation by:
  - financial year;
  - forecast source;
  - missing canonical `ticker + fiscal_year` result.
- Added priority ordering for missing facts by the number of forecast sources they unblock.
- Added **Покрытие фактическими результатами** panel to `/analytics/`.
- Added backend semantics tests and Playwright coverage.
- Added `docs/actual-result-coverage.md`.

## Coverage semantics

The denominator contains one historical `source + ticker + fiscal_year` forecast pair only when a finite net-profit forecast existed before the selected snapshot cutoff:

```text
pre_year  -> before January 1 of fiscal_year
mid_year  -> before July 1 of fiscal_year
year_end  -> before January 1 of fiscal_year + 1
```

The numerator contains those pairs for which canonical `actual_net_profits` has the same `ticker + fiscal_year`.

By default the endpoint looks at the last five **completed** financial years. Current and future years are excluded so missing final annual results do not mechanically depress coverage.

The response distinguishes:

- `missing_forecast_pairs` — source/ticker/year observations that cannot yet be scored;
- `missing_actual_records` — unique ticker/year actuals needed to unlock those observations.

## UI and privacy

The analytics panel shows:

- total coverage;
- covered / total historical forecast pairs;
- unique missing actual results;
- canonical actual-record count;
- coverage by year;
- coverage by source;
- priority missing ticker/year items.

Internet users continue to see masked analyst names through the existing analytics access layer.

## Production boundary

Actual Results Coverage is diagnostic only. This release does **not**:

- change the production median consensus;
- change source weights;
- expand controlled canary;
- enable auto-promotion;
- change forecast parsers or source cadence;
- change the primary universe;
- change Watchlist or volume-monitor behavior.

Coverage by itself is not evidence of forecast accuracy. It measures whether enough canonical actual data exists to evaluate the already captured forecasts.
