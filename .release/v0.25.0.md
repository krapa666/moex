# MOEX Fair Price v0.25.0

Minor release adding Forecast Source Health & Data Quality diagnostics to the main operational dashboard.

## Added

- Added public safe source-health endpoint:
  - `GET /api/dashboard/source-health?days=30`
- Added local-only detailed diagnostics endpoint:
  - `GET /api/dashboard/source-health/details?days=30`
- Added per-source states:
  - `HEALTHY`
  - `DEGRADED`
  - `STALE`
  - `FAILED`
- Added source freshness relative to each source's configured sync interval.
- Added coverage metrics and self-relative coverage-drop detection.
- Added run-history metrics:
  - success / partial / failed counts;
  - consecutive successes;
  - consecutive failures;
  - current run-in-progress flag.
- Added structured public error diagnostics without raw exception text.
- Added Dashboard **Прогнозные источники** panel with 7/30/90/180-day windows.
- Added backend/API and Playwright coverage.
- Added `docs/forecast-source-health.md` and updated `docs/forecast-sources.md`.

## Health policy

Freshness is relative to the actual configured cadence of each source:

```text
normal       <= 1.5x cadence
DEGRADED     >  1.5x cadence
STALE        >  2.5x cadence
```

For the default six-hour cadence:

```text
normal through 9h
DEGRADED after 9h
STALE after 15h
```

A latest completed `failed` run has priority and produces `FAILED` even when it is very recent.

A `partial` latest run produces `DEGRADED`.

### Coverage policy

Absolute coverage is reported but does not by itself degrade a source. This avoids penalizing a source that naturally covers a smaller stable universe.

`coverage_drop` requires:

- at least three prior comparable `success|partial` coverage observations;
- current coverage at least 10 percentage points below the median of the source's own recent baseline;
- at most ten prior runs are used for the baseline.

## Privacy

Public health does not expose:

- custom Published Sheets analyst names;
- raw exception text;
- ticker-level raw error details.

Custom Published Sheets are displayed as `Published Sheets #N` and use a hashed public source id.

Raw `analyst_name`, `error_message` and limited `error_details` are available only from the local-only details endpoint.

## Configuration contract

The backend now receives the existing forecast-source enabled/name/interval settings that were already passed to `arsagera-worker`, so health uses the same active-source and cadence configuration as the scheduler.

No new environment variables are introduced and no existing source schedules are changed.

## Production boundary

Unchanged:

- forecast parser logic;
- forecast synchronization cadence;
- primary universe;
- global median default;
- weighted/canary safety gates;
- current Watchlist and `stock_rows`;
- volume monitor.

Source health is diagnostic only. `FAILED` or `DEGRADED` does not automatically disable a source.

## Database and configuration

- Database migration required: **no**.
- Schema head remains `0024_canary_evidence`.
- Mandatory `.env` changes: **no**.
