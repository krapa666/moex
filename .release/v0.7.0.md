# MOEX Fair Price v0.7.0

Minor release adding historical analyst-consensus dynamics reconstructed from existing forecast revisions.

## Added

- Added **«Динамика консенсуса»** to `/analytics/?ticker=...`.
- The panel reconstructs the latest known state of every analyst table after each saved `forecast_revision` and calculates consensus for the primary table's forecast year.
- Added two independent historical charts:
  - **«Медианная цель»** — median comparable target price over saved revisions;
  - **«Разброс целей»** — `(MaxTarget - MinTarget) / MedianTarget × 100%` when at least two comparable targets exist.
- Added summary KPIs for:
  - number of distinct consensus-state changes;
  - latest reconstructed median target;
  - latest reconstructed spread;
  - number of comparable targets in the latest point.
- Added an exact recent-state list with timestamp, forecast year, median target, spread and target count so the charts are not the only carrier of values.
- Consecutive revisions that do not change consensus year, target count, median or spread are deduplicated from the aggregate series.
- Historical chart segments are not connected across a forecast-year change.

## Semantics and safety

- The feature uses only the existing `GET /api/analytics/forecast-revisions` API; no historical values are invented.
- Reconstruction starts only when a real saved revision exists for the primary table.
- Values that predate the `forecast_revisions` capture mechanism are not backfilled.
- Historical consensus always uses all available analyst tables for the ticker. The Analytics `Аналитик` filter continues to narrow the ordinary chronology and fair-value chart, but does not narrow consensus reconstruction.
- The API maximum of 500 revisions is respected. If the response reaches the limit, the panel states that only the latest 500 revisions were used.
- Analyst names are not rendered in the historical-consensus panel, so guest mode does not expose internal table names.

## Compatibility

- No database or migration changes.
- No new API route or response-schema changes.
- No changes to current consensus formulas, Arsagera sync, volume monitor, Watchlist score, dividend semantics or Compose topology.
