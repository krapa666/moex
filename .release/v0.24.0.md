# MOEX Fair Price v0.24.0

Minor release adding evidence-quality and capture-health diagnostics for the controlled weighted-consensus canary.

## Added

- Added public safe capture-health endpoint:
  - `GET /api/analytics/consensus-canary/evidence/health`
- Added explicit per-ticker and global health states:
  - `NOT_CONFIGURED`
  - `WARMING_UP`
  - `HEALTHY`
  - `DEGRADED`
  - `STALE`
- Added capture-quality metrics:
  - expected monitoring cadence;
  - age of latest snapshot;
  - observed intervals;
  - gap violations;
  - estimated missed cycles;
  - longest capture gap;
  - continuity percent;
  - global median continuity.
- Added target-year-safe gap accounting: target-year rollover does not create a false missing-cycle gap.
- Added explicit stale priority: a single old snapshot is `STALE`, not `WARMING_UP`.
- Added Analytics **Capture health** panel with 1/7/30/90 day windows and per-ticker reasons.
- Added backend/API and Playwright coverage.
- Added `docs/canary-evidence-health.md`.

## Health policy

Health uses the configured shadow/evidence cadence (`SHADOW_HISTORY_INTERVAL_HOURS`, default 6h).

Operational thresholds:

```text
fresh            <= 1.5x cadence
delayed          > 1.5x and <= 2.5x cadence
stale            > 2.5x cadence
probable gap     >= 1.75x cadence
```

For the default 6-hour cadence:

```text
fresh through 9h
stale after 15h
probable missed-cycle gap from 10.5h
```

These are monitoring thresholds, not statistical significance thresholds and not promotion criteria.

## Production boundary

Unchanged:

- global median remains the fail-safe default;
- maximum canary allowlist remains 5 tickers;
- canary enable/runtime safety gates remain unchanged;
- weighting formula remains unchanged;
- drift thresholds remain unchanged;
- no automatic canary expansion is introduced;
- current `/watchlist/`, `stock_rows`, source forecast data and volume monitor remain unchanged.

`HEALTHY` means the evidence stream is sufficiently fresh/continuous to interpret; it does **not** mean weighted should be promoted.

## Database and configuration

- Database migration required: **no**.
- Schema head remains `0024_canary_evidence`.
- Mandatory `.env` changes: **no**.
- Health reuses existing `SHADOW_HISTORY_INTERVAL_HOURS`.
