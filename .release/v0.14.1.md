# MOEX Fair Price v0.14.1

Patch release aligning operator documentation and Compose configuration with the current v0.14 application behavior.

## Fixed

- Fixed the volume scheduling environment contract.
- `.env.example` now uses the runtime variable `VOLUME_SCHEDULE_MINUTES=20,35,45` instead of the obsolete singular `VOLUME_SCHEDULE_MINUTE`.
- `docker-compose.yml` now passes `VOLUME_SCHEDULE_MINUTES` to both `backend` and `volume-worker`.
- Custom schedule minutes set in `.env` are therefore no longer silently ignored by Compose.
- Added regression tests covering the runtime parser and the `.env.example`/Compose variable name contract.

## Documentation

- Reworked README to match the current architecture: multi-source forecast worker, Analytics, Watchlist, source-run history, accuracy scoring and optional MOEX CCI actual-result synchronization.
- Documented the current Analytics accuracy/actual-result controls and APIs.
- Updated source-accuracy documentation for `source_key` ownership and MOEX CCI sync endpoints.
- Clarified that `.env.example` may contain empty credential placeholders but must never contain real secrets.
- Documented the current volume schedule as 18:20, 18:35 and 18:45 Europe/Moscow.
- Documented the current Alembic head `0020_actual_source_key`.

## Compatibility

- No database migration.
- No forecast, fair-value, consensus, Watchlist or volume-signal formula changes.
- Existing installations that do not override the schedule continue to run at 18:20/18:35/18:45.
- Existing `.env` files using only the obsolete `VOLUME_SCHEDULE_MINUTE` should be changed to `VOLUME_SCHEDULE_MINUTES` if a custom schedule is desired.

## Deployment

Use the normal Compose update path. No mandatory `.env` change is required for installations that use the default schedule.
