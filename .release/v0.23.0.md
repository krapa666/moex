# MOEX Fair Price v0.23.0

Minor release adding forward-only observability and evidence for the controlled weighted-consensus canary introduced in v0.22.0.

## Added

- Added persisted `canary_evidence_snapshots` history.
- Added forward-only capture of the **actually applied** Active consensus state:
  - configured mode;
  - effective mode;
  - safety state;
  - fallback reason;
  - median / weighted / active target;
  - median / weighted / active expected return.
- Canary evidence is captured inside the existing shadow monitoring cycle after shadow/drift processing.
- Added time-weighted canary metrics:
  - configured weighted hours;
  - weighted hours;
  - fallback hours;
  - weighted uptime;
  - fallback incidents;
  - recoveries;
  - longest weighted run;
  - longest fallback run;
  - fallback reason counts.
- Added target-year-safe transition accounting: year rollover never creates a false recovery and duration is not bridged across target years.
- Added public safe evidence APIs:
  - `GET /api/analytics/consensus-canary/evidence`
  - `GET /api/analytics/consensus-canary/evidence/ticker`
  - `GET /api/analytics/consensus-canary/evidence/history`
- Added local diagnostic capture:
  - `POST /api/analytics/consensus-canary/evidence/capture`
- Added Analytics UI:
  - global Canary Observability KPIs/table;
  - 1/7/30/90 day monitoring windows;
  - per-ticker Canary Evidence timeline after Active consensus.
- Added backend/API and Playwright coverage.
- Added `docs/canary-evidence.md` and refreshed project documentation.

## Methodology

Uptime is **time-weighted**, not row-weighted.

For two consecutive snapshots the elapsed interval is attributed to the state of the earlier snapshot. The final snapshot is not extrapolated forward to `now`; this prevents a stopped worker from artificially inflating uptime.

Fallback incidents count entries into `configured=weighted_canary / effective=median`, not every repeated fallback row.

Recovery is counted only when fallback returns to weighted inside the same target year and uninterrupted weighted-canary configuration.

## Forward-only boundary

v0.23.0 does not backfill canary evidence from historical forecast revisions or shadow snapshots.

The effective runtime canary guard before v0.23.0 cannot be reconstructed with sufficient confidence without hindsight risk. Evidence therefore starts with the first monitoring cycle after deployment.

## Production boundary

Unchanged:

- global median remains the fail-safe default;
- maximum canary allowlist remains 5 tickers;
- canary enable gates remain unchanged;
- runtime divergence/concentration/drift guards remain unchanged;
- there is no automatic canary expansion;
- current `/watchlist/` remains unchanged;
- `stock_rows`, volume monitor and source forecast data are unchanged.

v0.23.0 is an observability/evidence release only.

## Privacy

Public evidence endpoints contain only ticker-level aggregate operational state.

They do not expose:

- analyst/source names;
- individual source forecasts;
- source-level weights;
- SMTP/recipient information.

Manual evidence capture remains local-only.

## Database and configuration

- Database migration required: **yes**.
- New schema head: `0024_canary_evidence`.
- Backend startup applies Alembic automatically.
- Mandatory `.env` changes: **no**.
- Evidence retention reuses `SHADOW_HISTORY_RETENTION_DAYS` (default 730 days).
