# MOEX Fair Price v0.22.0

Minor release adding a controlled, fail-safe canary path for manually applying accuracy-weighted consensus to a small allowlist without replacing median as the default.

## Added

- Added persisted canary control state:
  - `consensus_canary_settings`
  - maximum allowlist: 5 tickers
  - default: disabled
- Added append-only audit trail:
  - `consensus_canary_events`
  - configure/reconfigure/enable/disable/rollback actions
  - optional operator note
  - promotion status captured on enable
- Added public safe status API:
  - `GET /api/analytics/consensus-canary`
- Added local-only control APIs:
  - `PUT /api/analytics/consensus-canary`
  - `POST /api/analytics/consensus-canary/rollback`
  - `GET /api/analytics/consensus-canary/events`
- Added public Active consensus API:
  - `GET /api/analytics/active-consensus?ticker=SBER`
- Added Analytics UI:
  - Controlled canary operator block in Production Impact Dashboard
  - local allowlist/note/enable/rollback controls
  - local audit trail
  - per-ticker Active consensus card
  - explicit `MEDIAN`, `WEIGHTED CANARY`, `MEDIAN FALLBACK` modes
- Added backend unit/API and Playwright coverage.
- Added `docs/consensus-canary.md` and refreshed README/Analytics documentation.

## Enable policy

Canary enable is fail-closed.

Required:

```text
promotion dossier                  READY_FOR_MANUAL_PROMOTION
ticker                             in primary universe
shadow weighted                    available
real historical weighting         >= 2 trained sources
live abs weighted/median delta     < 10%
live max-weight concentration      < 1.5x equal weight
forward drift                      STABLE
allowlist                          1..5 tickers
```

Equal-weight fallback is not accepted as production weighted canary.

## Runtime safety

Every Active consensus request for a configured canary ticker rechecks live safety.

Weighted is applied only while:

```text
historical weighting available
live divergence below WATCH
live concentration below WATCH
forward drift = STABLE
```

Otherwise:

```text
configured_mode = weighted_canary
effective_mode  = median
fallback_reason = <guard reason>
```

This is automatic demotion only. There is no automatic promotion or allowlist expansion.

## Active consensus methodology

Median remains the baseline.

For weighted canary, only the price-target layer changes. Dividend contribution is held constant from the median full-return baseline:

```text
MedianReturn = MedianPricePotential + DividendLayer
WeightedReturn = WeightedPricePotential + same DividendLayer
```

Median expected return is calculated only over the same source rows that have a comparable target price for the target year.

## Rollback

Rollback is always available from local scope regardless of current readiness/promotion status:

```http
POST /api/analytics/consensus-canary/rollback
```

Rollback only disables canary state. It does not rewrite forecasts or require a data restore.

## Production boundary

Median remains the fail-safe default.

v0.22.0 can change only the **Active consensus** result for explicitly selected canary tickers.

Unchanged:

- source analyst tables;
- `stock_rows` forecast/fair-value fields;
- current `/watchlist/` behavior;
- volume monitor;
- forecast revision history;
- weighting defaults;
- historical readiness gates;
- drift thresholds;
- shadow notification state machine.

## Privacy and access

Public safe:

- canary enabled/allowlist/status metadata;
- Active consensus aggregate/ticker-level result.

Local-only:

- configure/enable/disable;
- rollback;
- audit events.

No public endpoint exposes analyst/source identities, source-level forecasts or source-level weights.

## Database and configuration

- Database migration required: **yes**.
- New schema head: `0023_consensus_canary`.
- Backend startup applies Alembic automatically.
- Mandatory `.env` changes: **no**.
- Canary defaults to disabled after migration.
