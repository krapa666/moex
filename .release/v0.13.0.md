# MOEX Fair Price v0.13.0

Minor release adding the evidence layer required for future accuracy-weighted consensus.

## Added

- Added a canonical annual actual-net-profit ledger keyed by MOEX ticker and fiscal year.
- Added local-only create/update/delete API for factual annual net profit with source provenance.
- Added public read-only API for factual results.
- Added historical forecast-vs-actual scoring from saved `forecast_revisions`.
- Added three fixed no-hindsight forecast snapshots:
  - `pre_year` — latest forecast before January 1 of the fiscal year;
  - `mid_year` — latest forecast before July 1;
  - `year_end` — latest forecast before January 1 of the following year.
- Added source quality metrics:
  - median and mean sMAPE;
  - median and mean absolute error in billion RUB;
  - mean forecast bias;
  - profit/loss sign accuracy;
  - observation, ticker and fiscal-year coverage.
- Added ranking eligibility threshold; the UI requires at least 5 observations before a source receives a rank.
- Added detailed per-sample accuracy API for auditing every forecast-to-actual comparison.
- Added a new **Точность источников** block to `/analytics/` with snapshot selection, ranking and latest factual results.
- Added a local-only factual-result editor in Analytics; internet users keep read-only access and masked source names.
- Added database migration `0019_actual_net_profits` on top of v0.12.0 source-run observability.

## Methodology

The primary relative error metric is symmetric MAPE:

```text
sMAPE = 200 × |Forecast - Actual| / (|Forecast| + |Actual|)
```

sMAPE is used instead of ordinary MAPE because the company universe can contain losses and values near zero.

For each ticker/source/year/snapshot the scorer selects the latest saved forecast revision strictly before the fixed cutoff. Later revisions cannot improve an earlier historical score.

Eligible sources are ranked by lower median sMAPE, then lower mean sMAPE, then greater sample count.

## Safety

- Actual-result writes require explicit local network scope.
- `NaN` and infinite factual values are rejected.
- A restatement updates the canonical `ticker + fiscal year` record rather than creating two competing facts.
- A source with too little history remains visible but unranked.
- The factual ledger is independent from analyst forecast tables; an analyst forecast is never treated as a factual result automatically.

## Consensus compatibility

**v0.13.0 does not change current consensus weights or formulas.**

The accuracy ranking is observational evidence only. Weighted consensus remains intentionally disabled until the application has enough factual coverage and a separate backtest establishes safe weighting, shrinkage and sample-size rules.

The v0.12.0 `forecast_source_runs` observability API and history remain intact. No changes were made to Arsagera, DOHOD, fin-vista parsing, Published Sheets adapters, Watchlist scoring or volume monitoring.

## Deployment

- Database migration required: **yes** (`0019_actual_net_profits`).
- The supported backend container automatically runs `alembic upgrade head` on startup, so the normal Compose deployment command applies the migration.
- No mandatory `.env` changes.

See `docs/source-accuracy.md` for the complete methodology and API contract.
