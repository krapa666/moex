# MOEX Fair Price v0.11.0

Minor release adding persistent observability for automatic forecast sources.

## Added

- Added `forecast_source_runs` history for every built-in and configured forecast synchronization.
- Added stable source categories: `arsagera`, `dohod`, and `published-sheets`.
- Each run stores start/finish timestamps, status, table count, ticker coverage, update/unchanged/skip counts, table creation and per-ticker errors.
- Added explicit run statuses:
  - `success` — synchronization completed without source errors;
  - `partial` — at least one ticker failed or was unavailable while other tickers were mapped;
  - `failed` — the source could not provide usable mapping, or the synchronization raised an exception.
- Added `GET /api/analytics/source-runs` with filtering by source, analyst, status, start time and limit.
- Added tests for successful, partial and failed synchronization history and API ordering/filtering.

## Reliability

- Forecast ingestion remains fail-open with respect to observability: inability to write the run-history record is logged but does not block the forecast synchronization itself.
- Source exceptions are persisted as failed runs and are still re-raised to preserve the existing worker error semantics.
- Per-ticker errors remain isolated and are preserved in `error_details` for later diagnosis.

## Database

- Adds Alembic revision `0018_forecast_source_runs`.
- Existing forecast rows, revision history, volume history and source configuration are unchanged.

## Compatibility

- Existing source scheduling intervals and Compose service names are unchanged.
- Existing forecast and consensus formulas are unchanged.
- Existing `/api/analytics/forecast-revisions` contract is unchanged.

## Next step

The persisted run history is the data foundation for source freshness/coverage indicators on Dashboard and, only after enough observations accumulate, source-quality analysis.
