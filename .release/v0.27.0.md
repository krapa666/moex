# MOEX Fair Price v0.27.0

Minor release adding a safe local workflow for bulk backfill of historical canonical actual net-profit results.

## Added

- Added local-only multipart CSV preview endpoint:
  - `POST /api/analytics/actual-net-profits/backfill/preview`
- Added local-only multipart CSV apply endpoint:
  - `POST /api/analytics/actual-net-profits/backfill`
- Added UTF-8 CSV parsing with `;`, `,` and tab delimiter support.
- Added strict provenance requirements:
  - `source_name`;
  - absolute HTTP(S) `source_url`;
  - ISO-8601 `reported_at`.
- Added completed-fiscal-year validation.
- Added duplicate `ticker + fiscal_year` detection inside one CSV.
- Added all-or-nothing validation: any `INVALID` row blocks writes from that file.
- Added canonical-fact protection: bulk import never overwrites an existing `ticker + fiscal_year` record.
- Added local Analytics UI with:
  - generated CSV template;
  - preview;
  - `CREATE / UNCHANGED / PROTECTED / INVALID` row status;
  - explicit apply button after a valid preview.
- Added backend tests and Playwright coverage.
- Added `docs/actual-result-backfill.md`.

## Safety semantics

Bulk-imported records use:

```text
source_key=manual
```

This protects curated backfill data from later MOEX CCI auto-sync overwrites.

Existing canonical records are never replaced by bulk import. A differing existing row is classified as `PROTECTED` and skipped. Intentional corrections/restatements remain an explicit manual operation through the existing Analytics fact form.

If any CSV row is `INVALID`, apply creates zero records from the file.

## Forecast-history boundary

v0.27.0 does **not** reconstruct historical forecasts.

Actual-result backfill may increase `actual_records`, but Historical Actual Results Coverage can still show `forecast_pairs=0` until the application accumulates real `forecast_revisions` that existed before the relevant `pre_year`, `mid_year`, or `year_end` cutoff.

This is intentional. Reconstructing old forecasts from current values would introduce hindsight bias into source accuracy and consensus backtests.

## CSV contract

Required columns:

```text
ticker
fiscal_year
net_profit_billion_rub
source_name
source_url
reported_at
```

Optional:

```text
source_comment
```

Limits:

```text
max file size: 2,000,000 bytes
max data rows: 5,000
```

## Production boundary

Unchanged:

- production median consensus;
- source weights;
- controlled-canary allowlist and limits;
- auto-promotion policy;
- forecast parsers and source cadence;
- primary universe;
- Watchlist;
- volume monitor;
- MOEX CCI configuration.

## Database and configuration

- Database migration required: **no**.
- Existing `actual_net_profits` table is reused.
- Schema head remains `0024_canary_evidence`.
- Mandatory `.env` changes: **no**.
