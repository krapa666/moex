# MOEX Fair Price v0.12.0

Minor release adding persistent observability for automatic forecast sources.

## Added

- Added `forecast_source_runs` history for every forecast synchronization.
- Added stable source categories: `arsagera`, `dohod`, `fin-vista`, and `published-sheets`.
- Each run stores start/finish timestamps, status, table count, ticker coverage, update/unchanged/skip counts, table creation and per-ticker errors.
- Added explicit run statuses:
  - `success` — synchronization completed without source errors;
  - `partial` — at least one ticker failed or was unavailable while other tickers were mapped;
  - `failed` — the source could not provide usable mapping, or synchronization raised an exception.
- Added `GET /api/analytics/source-runs` with filtering by source, analyst, status, start time and limit.
- Added tests for successful, partial and failed synchronization history and API ordering/filtering.

## Reliability

- Forecast ingestion remains fail-open with respect to observability: inability to write run history is logged but does not block the synchronization itself.
- Source exceptions are persisted as failed runs and still re-raised to preserve existing worker error semantics.
- Per-ticker errors remain isolated and are retained in `error_details` for diagnosis.

## Database

- Adds Alembic revision `0018_forecast_source_runs`.
- Existing forecast rows, forecast revision history, volume history and source configuration are unchanged.

## Compatibility

- Existing source scheduling intervals and Compose service names are unchanged.
- Existing fair-price and consensus formulas are unchanged.
- Existing `/api/analytics/forecast-revisions` contract is unchanged.
- fin-vista remains disabled by default; this release only adds run-history tracking when it is enabled.

## Next step

Use the persisted run history to expose source freshness and coverage on Dashboard. Source-accuracy scoring should wait until enough historical observations exist for a meaningful comparison.
