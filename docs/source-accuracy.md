# Точность источников прогнозов

## Назначение

Начиная с v0.13.0 MOEX Fair Price хранит отдельный канонический факт годовой чистой прибыли и может сравнивать его с историческими ревизиями прогнозов.

Этот слой нужен для будущего взвешенного консенсуса, но **сам по себе не меняет текущие формулы consensus, fair value, Watchlist или доходности**. Сначала должна накопиться достаточная история сопоставимых пар `прогноз -> факт`.

## Канонический факт

Фактическая чистая прибыль хранится отдельно от таблиц аналитиков в `actual_net_profits`.

Для каждой пары `тикер + финансовый год` существует одна текущая каноническая запись:

- `net_profit_billion_rub` — фактическая чистая прибыль в млрд рублей;
- `source_name` — название первичного источника факта;
- `source_url` — необязательная ссылка на источник;
- `source_comment` — необязательное пояснение;
- `reported_at` — дата публикации результата, если она известна.

Повторное сохранение той же пары `тикер + год` обновляет существующую запись. Это позволяет корректно учитывать рестейтменты, не создавая два конкурирующих «факта».

Предпочтительный источник факта — официальный годовой результат эмитента по выбранному стандарту отчётности. Нельзя использовать прогноз того же аналитика как фактический результат.

Запись и удаление фактов разрешены только из локального режима (`X-Moex-Access-Scope: local`). Чтение фактов и агрегированной статистики остаётся доступным в read-only режиме.

## Срезы прогноза

Для одного и того же финансового года точность можно измерять на трёх фиксированных датах:

| Срез | Отсечка | Смысл |
| --- | --- | --- |
| `pre_year` | 1 января финансового года | Что источник ожидал до начала года |
| `mid_year` | 1 июля финансового года | Насколько точен прогноз после первого полугодия |
| `year_end` | 1 января следующего года | Последняя оценка до завершения календарного года |

Для каждого источника, тикера и года берётся **последняя сохранённая ревизия строго раньше отсечки**, в которой есть прогноз чистой прибыли нужного года.

Ревизии после отсечки не используются. Поэтому более поздний прогноз не может задним числом улучшить статистику предыдущего среза.

## Метрики

Основная относительная метрика — symmetric mean absolute percentage error (sMAPE):

```text
sMAPE = 200 × |Forecast - Actual| / (|Forecast| + |Actual|)
```

Если и прогноз, и факт равны нулю, ошибка считается равной 0%.

sMAPE используется вместо обычного MAPE, потому что в истории российских компаний возможны убытки и значения около нуля. Обычный MAPE в таких случаях становится неустойчивым или вообще неопределённым.

Для каждого источника также считаются:

- `median_smape_percent` — медианная sMAPE;
- `mean_smape_percent` — средняя sMAPE;
- `median_absolute_error_billion_rub` — медианная абсолютная ошибка в млрд ₽;
- `mean_absolute_error_billion_rub` — средняя абсолютная ошибка в млрд ₽;
- `mean_bias_billion_rub` — среднее значение `Forecast - Actual`; положительное значение означает систематическое завышение прогноза, отрицательное — занижение;
- `sign_accuracy_percent` — доля случаев, где источник правильно предсказал знак результата: прибыль / убыток / ноль;
- число наблюдений, уникальных тикеров и финансовых лет.

## Рейтинг

По умолчанию источник получает место в рейтинге только при наличии минимум **5 наблюдений** для выбранного среза.

Сортировка среди допущенных источников:

1. меньшая медианная sMAPE;
2. меньшая средняя sMAPE;
3. большее число наблюдений;
4. имя источника как стабильный tie-breaker.

Источник с меньшим числом наблюдений остаётся видимым, но получает статус «недостаточно наблюдений» и не получает ранг. Поэтому одна случайно точная оценка не делает новый источник автоматически лучшим.

Порог `min_samples` можно менять через API для исследования, но интерфейс v0.13.0 использует консервативное значение `5`.

## API

Чтение фактов:

```http
GET /api/analytics/actual-net-profits
GET /api/analytics/actual-net-profits?ticker=SBER&fiscal_year=2025
```

Локальная запись или рестейтмент:

```http
PUT /api/analytics/actual-net-profits/SBER/2025
Content-Type: application/json

{
  "net_profit_billion_rub": 1580.3,
  "source_name": "МСФО, отчёт эмитента",
  "source_url": "https://..."
}
```

Локальное удаление:

```http
DELETE /api/analytics/actual-net-profits/SBER/2025
```

Агрегированная точность:

```http
GET /api/analytics/source-accuracy?snapshot=pre_year&min_samples=5
```

Детальные пары `прогноз -> факт`:

```http
GET /api/analytics/source-accuracy/samples?snapshot=pre_year
```

Детальный endpoint поддерживает фильтры `ticker`, `analyst_name`, `fiscal_year` и `limit`.

## Интерфейс

На странице `/analytics/` появился блок **«Точность источников»**:

- выбор среза прогноза;
- рейтинг и метрики источников;
- последние канонические факты;
- локальная форма добавления/обновления факта.

В интернет-режиме реальные названия источников маскируются тем же механизмом `Аналитик N`, что используется в остальных блоках Analytics. Форма изменения фактов скрыта.

## Почему weighted consensus ещё не включён

Вес источника нельзя надёжно вывести только из нескольких новых наблюдений. Кроме того, точность зависит от горизонта: источник может быть слабым до начала года и сильным после полугодия.

Поэтому v0.13.0 только собирает и измеряет evidence. Следующий этап должен отдельно определить:

- минимальное покрытие для использования веса;
- какой исторический срез соответствует текущему времени до прогнозного года;
- shrinkage к равному весу при малой выборке;
- ограничение максимального/минимального веса;
- поведение при отсутствии истории у нового источника;
- backtest weighted consensus против обычной медианы.

До выполнения этого этапа текущий consensus остаётся неизменным и не использует рейтинг точности автоматически.
