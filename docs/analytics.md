# Analytics

Страница `/analytics/` объединяет текущий срез оценок по выбранному тикеру и историю сохранённых ревизий прогнозов.

## Режим доступа и имена аналитиков

Analytics использует тот же сетевой режим доступа, что и основная таблица оценок:

- локальный клиент, для которого `/api/auth/me` возвращает `is_admin = true`, видит реальные `analyst_name`;
- интернет-клиент работает как гость и видит только нейтральные подписи `Аналитик 1`, `Аналитик 2` и т. д.;
- если состояние доступа не удалось определить, Analytics безопасно трактует клиента как гостя.

Маскирование применяется единообразно к селектору аналитика, текущему consensus, блоку изменений за сегодня, хронологии и легенде/tooltip графика. Номер берётся из `table_number`, а для исторической записи сопоставляется с её `table_id` через текущий каталог `/api/tables`.

## Текущий консенсус

Блок **«Консенсус аналитиков»** использует существующий `GET /api/ticker-comparison?ticker=...` и не создаёт отдельный источник данных.

Правила расчёта:

- базовый прогнозный год берётся из основной таблицы (`table_number = 1`);
- в диапазон включаются только аналитики, у которых есть текущая `forecast_price` именно на этот год;
- цели на другой прогнозный год не смешиваются с базовым горизонтом;
- минимум и максимум считаются по сопоставимым целевым ценам;
- медиана для нечётного числа целей — центральное значение после сортировки;
- медиана для чётного числа целей — среднее двух центральных значений;
- показатель **«Рынок»** — медиана доступных `current_price` из ответа сравнения; в нормальном состоянии эти цены совпадают, потому что тикер общий между таблицами.

Визуальный диапазон показывает положение каждой сопоставимой цели между минимумом и максимумом. Под диапазоном выводится точный список аналитиков и целевых цен, поэтому графика не является единственным носителем значения.

Если у части аналитиков прогнозный горизонт сдвинут и базовый год отсутствует, они не участвуют в min/median/max. Статус блока показывает число использованных целей относительно общего числа таблиц, например `2026 · целей: 2/3`.

### Полная доходность консенсуса

Для тех же сопоставимых целей базового года Analytics использует уже рассчитанный backend `upside_percent`. Это тот же показатель полной ожидаемой доходности, что отображается в основной таблице: он учитывает изменение цены и оставшиеся дивиденды от текущего дня до выбранного прогнозного года.

В consensus выводятся два показателя:

- **«Медианная доходность»** — медиана всех доступных `upside_percent` среди сопоставимых целей базового года;
- **«Положительных»** — число прогнозов с полной доходностью `> 0%` относительно числа сопоставимых целей, для которых `upside_percent` рассчитан.

Если у конкретной сопоставимой цели `upside_percent` отсутствует, она продолжает участвовать в ценовом диапазоне min/median/max, но не участвует в медиане полной доходности и счётчике положительных прогнозов. Если рассчитанной доходности нет ни у одной цели, оба доходностных показателя отображаются как недоступные.

Цели аналитиков другого прогнозного года не участвуют и в доходностной медиане. Поэтому ценовой consensus и доходностный consensus всегда относятся к одному и тому же горизонту.

### Разброс и согласованность

Для сопоставимых целей одного года дополнительно рассчитывается относительный разброс:

```text
SpreadPercent = (MaxTarget - MinTarget) / MedianTarget × 100%
```

Категория **«Согласованность»** определяется только этим прозрачным показателем:

- `≤ 10%` — **высокая**;
- `> 10%` и `≤ 25%` — **средняя**;
- `> 25%` — **низкая**.

Это не оценка качества аналитиков и не инвестиционный рейтинг. Показатель отвечает только на вопрос, насколько широко текущие сопоставимые цели расходятся относительно медианной цели.

Для одной сопоставимой цели согласованность не определяется: поле разброса показывает `—`, а категория — **«Недостаточно данных»**. Нулевое расхождение одной цели с самой собой не трактуется как высокая согласованность.

## История прогнозов

История по тикеру загружается из `GET /api/analytics/forecast-revisions` и остаётся отдельной от текущего консенсуса:

- consensus показывает текущие значения таблиц;
- chronology показывает сохранённые изменения прогнозов во времени;
- фильтр аналитика влияет на историю и график ревизий, но не сужает текущий consensus — он по определению сравнивает всех доступных аналитиков для выбранного тикера.

Рыночное обновление цены без изменения прогнозных входных данных не создаёт ревизию истории.
