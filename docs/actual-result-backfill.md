# Historical Actual Results Backfill

Начиная с v0.27.0 приложение поддерживает безопасный массовый импорт исторических фактических значений годовой чистой прибыли в канонический реестр `actual_net_profits`.

Цель функции — заполнить исторические факты, когда лицензируемый MOEX CCI не используется или историческое покрытие CCI недостаточно.

Backfill касается **только фактических результатов**. Он не создаёт и не реконструирует старые `forecast_revisions`.

## Почему прогнозная история не backfill-ится

Историческая точность должна использовать только прогноз, который действительно существовал до выбранного cutoff.

Нельзя взять сегодняшнее значение прогноза и записать его задним числом как будто оно было известно в 2022, 2023 или 2024 году. Такая реконструкция создаёт hindsight bias и делает accuracy/backtest недостоверными.

Поэтому v0.27.0 может увеличить `actual_records`, но `forecast_pairs` в Actual Results Coverage останется равным нулю, если приложение ещё не накопило настоящую историческую прогнозную историю до соответствующих cutoff.

Это нормальный и честный результат.

## Доступ

Bulk backfill доступен только из `local` scope.

Интернет-пользователь не видит форму импорта и не может вызвать write endpoint.

API:

```text
POST /api/analytics/actual-net-profits/backfill/preview
POST /api/analytics/actual-net-profits/backfill
```

Оба endpoint принимают multipart upload с полем `file`.

## Безопасная схема работы

Импорт всегда выполняется в два этапа:

```text
CSV
 ↓
preview
 ↓
CREATE / UNCHANGED / PROTECTED / INVALID
 ↓
explicit apply
```

`preview` не меняет БД.

`apply` создаёт только строки `CREATE`.

Bulk import **никогда не перезаписывает существующий канонический факт**.

Если `ticker + fiscal_year` уже существует и данные отличаются, строка получает статус:

```text
PROTECTED
```

Для сознательной корректировки или рестейтмента существующей записи используется существующая ручная форма Analytics. После ручного изменения запись остаётся `source_key=manual` и защищена от автоматической MOEX CCI синхронизации.

## All-or-nothing validation

Если CSV содержит хотя бы одну строку `INVALID`, apply не создаёт **ни одной** новой записи из этого файла.

Сначала файл нужно исправить и повторно выполнить preview.

`PROTECTED` не является синтаксической ошибкой файла и не блокирует создание других новых строк: конфликтующая существующая запись просто пропускается.

## Формат CSV

Файл должен быть UTF-8. Допустимые разделители:

```text
;
,
TAB
```

Это позволяет использовать как обычный CSV, так и типичный экспорт Excel с `;` и десятичной запятой.

Обязательные колонки:

```text
ticker
fiscal_year
net_profit_billion_rub
source_name
source_url
reported_at
```

Необязательная колонка:

```text
source_comment
```

Пример:

```csv
ticker;fiscal_year;net_profit_billion_rub;source_name;source_url;reported_at;source_comment
SBER;2025;1580,3;МСФО · отчёт эмитента;https://example.com/report;2026-02-27;ЧП, относимая к акционерам материнской компании
```

## Семантика полей

### `ticker`

Биржевой тикер. Нормализуется в uppercase.

Разрешены латинские буквы, цифры, `.`, `_` и `-`.

### `fiscal_year`

Только завершённый финансовый год.

Текущий календарный год импортировать нельзя, потому что финальный годовой факт ещё может отсутствовать или быть неполным.

### `net_profit_billion_rub`

Чистая прибыль в **млрд ₽**.

Отрицательное значение допустимо для убытка.

Значение должно быть конечным числом.

### `source_name`

Краткое название первичного источника, например:

```text
МСФО · отчёт эмитента
Годовой отчёт эмитента
```

### `source_url`

Обязательный абсолютный `http://` или `https://` URL на источник.

Bulk import намеренно не принимает факт без provenance URL.

### `reported_at`

Дата или timestamp публикации отчётности.

Допустимы ISO-8601 значения, например:

```text
2026-02-27
2026-02-27T18:00:00+03:00
2026-02-27T15:00:00Z
```

Дата не может находиться в будущем.

Если timezone не указана, значение интерпретируется как UTC.

### `source_comment`

Необязательное пояснение методологии. Рекомендуется указывать, какой именно показатель использован, особенно если в отчёте присутствует несколько вариантов чистой прибыли.

## Fail-closed проверки

Строка считается `INVALID`, если:

- тикер пуст или имеет неподдерживаемые символы;
- год не завершён;
- значение ЧП не является конечным числом;
- `source_name` пуст;
- `source_url` отсутствует или не является абсолютным HTTP(S) URL;
- `reported_at` отсутствует, не распознаётся или находится в будущем;
- в одном CSV повторяется один `ticker + fiscal_year`;
- превышены ограничения длины полей.

Ограничения файла:

```text
максимальный размер: 2 000 000 bytes
максимум строк:      5 000
```

## UI

В локальной Analytics внутри блока **Фактическая годовая чистая прибыль** появляется секция **Исторический backfill фактической ЧП**.

Доступно:

- создание CSV-шаблона;
- выбор локального CSV;
- preview;
- построчный статус;
- отдельная кнопка apply, активная только после успешного preview.

Статусы:

```text
CREATE      новая запись будет создана
UNCHANGED   полностью совпадающий факт уже существует
PROTECTED   ticker/year уже существует и bulk import его не меняет
INVALID     ошибка входных данных; apply заблокирован
```

## API из консоли

Preview через loopback backend:

```bash
curl -sS \
  -H 'X-Moex-Access-Scope: local' \
  -F 'file=@actuals.csv;type=text/csv' \
  http://127.0.0.1:18000/api/analytics/actual-net-profits/backfill/preview \
  | python3 -m json.tool
```

Apply:

```bash
curl -sS \
  -H 'X-Moex-Access-Scope: local' \
  -F 'file=@actuals.csv;type=text/csv' \
  http://127.0.0.1:18000/api/analytics/actual-net-profits/backfill \
  | python3 -m json.tool
```

После импорта проверить:

```bash
curl -sS 'http://127.0.0.1:18000/api/analytics/actual-net-profits?limit=200' \
  | python3 -m json.tool

curl -sS \
  'http://127.0.0.1:18000/api/analytics/actual-net-profits/coverage?snapshot=pre_year&years=5&missing_limit=20' \
  | python3 -m json.tool
```

## Связь с MOEX CCI

Bulk-import записи создаются как:

```text
source_key=manual
```

Поэтому последующая автоматическая MOEX CCI синхронизация не может их перезаписать.

Если нужен другой факт для уже существующего `ticker/year`, решение должно быть осознанным ручным изменением, а не автоматическим массовым overwrite.

## Что v0.27.0 не делает

Релиз не:

- реконструирует исторические прогнозы;
- изменяет production median;
- изменяет веса источников;
- расширяет controlled canary;
- включает auto-promotion;
- изменяет MOEX CCI credentials/configuration;
- создаёт новую таблицу БД;
- изменяет Watchlist или volume monitor.

## Database и configuration

Новая migration не требуется.

Используется существующая таблица:

```text
actual_net_profits
```

Новых обязательных `.env` параметров нет.
